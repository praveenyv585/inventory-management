Data Flow — Filter to Display
1
User adjusts a filter FilterBar.vue updates a ref in useFilters() — e.g. selectedLocation = "London". The composable uses module-level refs, so the same state instance is shared across all views.
2
View watcher fires Each view watch([selectedLocation, selectedCategory, selectedStatus, selectedPeriod], loadData) — the watcher calls the view's loadData() function.
3
API call with query params api.js calls getCurrentFilters(), builds a URLSearchParams object (omitting any value equal to 'all'), and fires an Axios GET — e.g. GET /api/orders?warehouse=London&status=Delivered.
4
Backend filters in memory main.py receives params, passes the in-memory list through apply_filters() (warehouse / category / status) then filter_by_month(). Month strings like Q2-2025 are expanded to ['2025-04','2025-05','2025-06'].
5
Pydantic validates & serialises FastAPI runs the filtered list through Pydantic models before serialising to JSON. Invalid or missing fields are caught here before reaching the frontend.
6
Vue re-renders The view stores the response in a ref (e.g. orders). Computed properties derived from that ref (charts, aggregates, sorted tables) recalculate automatically. Template re-renders via Vue's reactivity system.

State Management — Composables
useFilters()
Singleton — module-level refs shared across all views. No Pinia/Vuex needed.
  • selectedPeriod (month / quarter / all)
  • selectedLocation (warehouse)
  • selectedCategory
  • selectedStatus
  • hasActiveFilters (computed)
  • getCurrentFilters() → API params
  • resetFilters()
useI18n()
Language switching (EN / JA). Locale stored in localStorage. Currency auto-set.
  • currentLocale ref
  • currentCurrency computed (USD / JPY)
  • t() — translation lookup
  • translateCategory / translateWarehouse
  • translateProductName / CustomerName
useAuth()
Mock user session. No real auth — stub for future implementation.
  • currentUser (language-aware name)
  • isAuthenticated ref
  • logout() stub
  • 4 localised mock tasks
